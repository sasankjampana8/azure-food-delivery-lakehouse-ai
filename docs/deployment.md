# Deploying to an existing Azure environment

1. Provision the resource group, source Blob storage, `stfooddeliverylake` with hierarchical namespace and `landing`, `syn-food-delivery-dev` and its `sparkfooddev` Spark pool, and `adf-food-delivery-sasank`. Configure network/firewall access and the managed identity permissions for Blob/ADLS and Synapse artifacts. The ARM export does not create these foundations or the serverless SQL views.
2. Upload the six source CSVs to the source container. Create the three Gold serverless SQL views pointing to `landing/gold/<view_name>/`, using `OPENROWSET(... FORMAT='DELTA')`. Existing view SQL must be exported from the working workspace; it is not in this package.
3. For manual notebook setup, import four `synapse/notebooks/*.ipynb` files, mark each first `ROOT = ""` cell as a parameter cell and publish. Set the ADF notebook base parameter `ROOT` to the landing container ABFSS URL.
4. To use GitHub Actions: create an Entra application/service principal with a federated GitHub credential restricted to the repository and deployment environment; grant only required ADF resource-group deployment and Synapse artifact permissions. In GitHub create environment `azure-dev` with required reviewers. Define repository secrets `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, and variables `AZURE_RESOURCE_GROUP`, `AZURE_SYNAPSE_WORKSPACE`, `AZURE_FACTORY_NAME`, `AZURE_STORAGE_ACCOUNT`, `AZURE_SOURCE_STORAGE_ACCOUNT`.
5. Run CI first. Check the manual `deploy` workflow's plan and run it only for the intended environment. It is a template for the existing resources; check GitHub Actions output and then run the pipeline in ADF Monitor. Workflow execution has not yet been verified against this subscription.

The current ADF template was exported from a running factory. Its Synapse linked service resource ID is parameterized to the chosen resource group and workspace. On deployment the storage URLs and factory name are passed as ARM parameters. An ADF publish/export captures only ADF objects: notebooks, SQL scripts/views, Spark pools, storage and role assignments require their own lifecycle.
